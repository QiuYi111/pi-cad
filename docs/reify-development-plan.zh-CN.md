## 1. 本轮要交付的产品

Reify 是以成果画布为中心的工程 Agent。用户用对话表达意图，在画布检查、操作和比较成果，再通过对话或参数提出修改。

没有可看成果时，主区展示完整对话。首个概念图、CAD 或其他可交互成果就绪后，对话平滑收到底部，成果接管画布。用户随时用固定按钮或快捷键切回对话；切换保留输入、视角、选择和上下文。

本轮优先级：安装与首次使用、大画布与日常交互、失败恢复、正式交付。直接影响这些体验的底层问题随流程修复；不等待全部架构整理完成才开始 UI/UX。

成功标准：没有接触过项目的工程师，能独立安装，提出需求，查看成果，修改一个尺寸，处理一次失败并导出；正式交付用户能判断检查与批准是否适用于当前版本。

## 4. 大画布交互规范

### 4.1 稳定布局

顶部保留项目、当前成果/版本、任务状态和固定模式切换入口。项目导航可收起。主画布尽量占满剩余空间，右侧只展开当前操作需要的面板。底部只有一个主要输入位置。

对话有三档：仅输入、最近消息、完整对话。默认在有成果时仅显示输入；最近消息由用户展开。选中部位后，“让 Reify 修改”聚焦同一个输入框，并带上可移除的对象与版本引用。

生成、失败、审查通过都不更换主布局或重置视角，只更新状态和对应面板。关闭面板后任务状态仍可见。

### 4.2 状态变化

| 事件 | 画布与对话行为 |
| --- | --- |
| 无成果 | 完整对话，支持参考文件、澄清和任务入口 |
| 首个成果可用 | 平滑收起对话；用户正在输入或阅读时只提示成果就绪 |
| 后续成果可用 | 更新成果列表并提示，尊重用户当前查看对象 |
| 选中对象 | 显示对应工具与引用入口，不增加第二个聊天框 |
| 构建失败 | 保留上一可用成果，显示失败修改、依据与恢复操作 |
| 返回历史/对话 | 保留各成果视角、选择、草稿与滚动 |
| 应用重启 | 恢复项目和会话；中断任务显示真实状态与可执行下一步 |

动效用于首次收起、成果替换、检查定位与批准反馈；时长先采用短动效并在原型验证。支持减少动画。持续计算可有状态指示，但不靠无意义动画伪装进度。

### 4.3 不同成果的操作

| 内容 | 操作与边界 |
| --- | --- |
| CAD | 旋转、缩放、测量、剖切、零件选择/隐藏/隔离；有绑定才直接改参数 |
| 概念图 | 画板、缩放、并排、圈选、批注、选定方向；不是可测量的工程模型 |
| 仿真 | 量名、单位、色标、探针、切片、时间步、变形；显示设置与求解输入分开 |
| Blender | 场景预览、相机、渲染；完整原生界面先验证一个平台，外部编辑返回是明确的可行退路 |
| 图表与报告 | 查看、引用、来源追踪，与生成它的模型版本关联 |
| 比较 | 从两个成果或版本发起，使用并排/同步视角；不作为一种成果类型 |

成果列表显示类型、名称、版本、来源和有效性。类型筛选与成果列表避免重复占位；视角缩略图、方案和版本不能混在同一无标签列表。面板可停靠、可关闭，提供恢复布局；不默认要求用户整理任意漂浮窗口。

### 4.4 运行中输入

默认“当前任务完成后执行”，排队消息可修改和取消。“停止并修改”确认旧任务结束后启动新需求。“仅记备注”不自动执行。后端确有可说明的安全步骤时，才增加“当前步骤之后”。

显示思考中、工具执行、等待用户、失败、已停止、完成。没有可靠进度分母时显示步骤与耗时，不能照参考图填写百分比或剩余时间。选择、草稿、任务与排队消息始终归属明确项目和对话。

## 5. 视觉与可用性验收

品牌保留 Reify · 器成标志。参考色：Obsidian #0E0E0E、Graphite #646464、Stone #E8E6E1、Sage #5B6F63、Champagne #C9B89F。实际正文与背景组合必须检查对比度；参考色不意味着所有组合均可读。

暖白用于应用表面，深绿用于主要操作。红色只用于错误，“上一版已保留”使用中性或成功状态。石材、金属纹理与大标题主要用于欢迎和安装，工程画布保持简洁。品牌标题可用克制衬线，中文正文、工具和参数使用易读无衬线；数值与日志用等宽字体。状态不能只靠颜色区分。

每个 UI 切片都包含：1366×768、1920×1080、系统缩放、键盘焦点、中文长文本、空状态、加载、失败和恢复。高缩放时面板收起或滚动，主操作不被遮挡。各票交付实际页面，不设一个只有设计变量、没有用户结果的前置大工程。

建议初始体验目标：本地操作确认在 300ms 内可见，网络或计算任务在 1s 内显示已受理或明确异常；这是待测目标，不是当前性能声明。模型就绪与总任务耗时记录真实基线，不用统一秒数掩盖任务差异。

## 6. 工程控制如何服务体验

- 保存并检查：构建、必要检查、视图和记录合为完整操作；按所选流程执行，不固定强制所有任务七视图。
- 提交审查：候选与证据整理、权限检查和状态更新内部完成；重复请求不重复审查。
- 恢复源码：保护当前修改、固定重建输入、核对成果；不可复现时明确说明。
- 发布当前版本：核对源码、产物、有效批准，再生成可核验交付包；远端 Git 另行显式启用。

这些操作复用现有 authorize、事务与工作流，不增加第二套状态机。每一步记录已完成行为及恢复位置；重试不能重复提交或发布。

流程模板为 quick-check、quick-build、controlled-change、one-shot、release。任务开始时 Agent 可建议模板，用户看得到；组织政策限制可选范围。开放设计需要澄清或概念探索时再启用对应义务。升级流程必须补齐必要检查，不能通过换模板绕过发布控制。

检查摘要、机器审查、人工批准、用户评分分别保存与显示。批准绑定身份、项目、流程哈希、源码版本、产物哈希和范围；修改后过期，撤销后失效，发布时再次核对。未验证不显示为通过，批准不自动意味着可以制造。

正式交付默认是本地包：模型、按任务需要的图纸/报告、源码和输入说明、检查摘要、批准与文件清单。Git 远端发布是独立步骤；源码推送与产物交付各自显示结果。

规则固定实际任务依赖，同时保留独立全局安全规则。技能、流程、执行代码一起版本化；新任务显式采用新版，旧任务不被静默改变。蒸馏先生成候选，实际失败回放和保留任务回归后才批准采用。

## 7. 三平台安装与首次使用

共同流程：打开应用 → 检查基础环境 → 登录 → 选择项目位置 → 首个任务 → 查看/修改/导出。引导使用统一品牌，步骤和报错使用普通中文。管理员可以预装环境，工程师复用配置。代理、网络不可用或权限受限时明确指出受阻步骤。

基础 CAD 先可用，Blender、求解器和高级后处理按需准备。下载、安装、启动检查分别显示真实状态；可取消、可重试、可跨重启恢复。凭据不进日志或项目，诊断导出默认去除敏感内容。

| 平台 | 交付方式与验证 |
| --- | --- |
| Windows | 复用现有安装包；已有 WSL 与全新启用分开验证，重启可续接，路径及发行版清楚 |

## 9. 纵向切片规则与共同完成标准

按 to-tickets skill 拆分：一票完成一个窄而完整的用户行为，贯穿实际需要的数据、权限、执行、界面与验证。每票可在前置票完成的环境中独立演示，工作量应容纳一次独立开发上下文；发现超出时先继续切小行为，而不是拆成“先做前端/后端”。

每票先检查当前实现，必要的小范围整理先做并保持行为。新调用路径逐步取代重复旧路径；旧运行兼容保留到迁移完成。只有机械式全仓替换确实无法独立保持通过时，才用“并存 → 分批迁移 → 删除旧形式”，明确例外与验证点，不让全仓重构阻塞第一条体验。

共同完成条件：

- 用户入口、真实执行、成果/状态保存、失败处理、再次打开均适用且可用。
- 通过公共操作验证成功和一个相关失败路径；测试验证用户结果，不只验证内部函数形状。
- Agent 功能使用真实 Prime、sidecar、Python、Viewer；演示运行时仅用于视觉快照。
- Python 环境使用 uv；相关测试使用 uv run python。
- UI 使用真实数据的截图或短录屏；核心操作可键盘完成，小屏与缩放不遮挡。
- 记录提交、环境、输入、产物哈希、耗时、费用与恢复结果；不在日志记录凭据。
- 当前分支已有改动必须先核对并保留；不把合并他人修改或“主分支干净”当作用户功能验收。
- 不在每票重复跑全部跨平台矩阵；运行与改动相关的验证，发布时再汇总目标平台关键路径。
- 所有前置完成才进入可开工队列。编号是引用，不是要求严格串行排期。

## 11. 测试与发布门槛

截至 2026-09-05，当前实现通过根目录 TypeScript 全量测试 300/300、桌面端测试 69/69、桌面生产构建、Linux deb/AppImage 包内容检查及 `git diff --check`。Windows NSIS 已在当前 Windows 主机验证安装、启动、快捷方式、卸载项、bundled runtime、已有项目恢复和真实参数修改；当前包未签名，因此不能作为企业正式发行包。Linux 包已构建，AppImage 已在 WSL 启动；打包后的 Linux executable 已完成 native runtime、真实 STEP、坏文件恢复与导出验证。这些证据不能替代干净桌面 Ubuntu 验收。

剩余门禁有明确外部依赖：真实 ChatGPT OAuth；无 WSL 的干净 Windows VM；干净 Ubuntu 上的 deb/AppImage 首次任务、卸载和双版本升级回退；macOS 14+ Apple silicon 主机、Developer ID 与公证凭据、双版本升级回退；未接触项目的工程师可用性测试；固定模型、任务、环境和预算下的团队对照样本。对应切片提供执行脚本、记录 schema 与判定规则，任何一项没有真实证据时都不得在发布说明中声称支持。

固定任务至少包括：只读 STEP 检查、单零件建模、孔径修改、失败圆角修复、多实体装配局部修改、概念选图、小型仿真、Blender 场景编辑、正式批准交付。每个任务有独立可核验结果；新增切片把对应任务加入回归。

关键异常：OAuth 过期/取消/断网、依赖缺失、项目切换、中止/超时/重启、过期预览、Reviewer 中断、Git 冲突、批准撤销、发布目录不可写。安装按已声明支持的平台真实执行。

体验测试记录完成率、求助次数、卡点、首个反馈、总耗时。工程测试记录验收通过率、误通过率、人工介入、恢复成功率与费用。对照保持任务、模型、环境和预算一致；历史泄漏或不同版本数据不能混用。

对外发布必须通过：安装后首个任务、切换与重启恢复、参数修改和失败恢复、导出；若宣称正式交付则增加批准与交付包验证；若宣称仿真或 Blender 则增加对应真实路径。记录已知限制、安装包、版本说明和回退方法。没有实测的平台或能力不得标为支持。
