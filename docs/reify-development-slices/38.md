# 38：正式交付流程与收益对照

**状态：** 对照与报告工具完成；真实样本采集待进行。

**交付结果：** 工程团队从受控修改到批准交付，验证可信程度，并比较新增机制的实际收益。

**前置依赖：** 23 生成可核验的正式交付包；25 选择固定规则版本并回退；37 新工程师完成第一条真实流程。

**验收条件：**

- [x] 对照协议固定 model/task/environment/budget，定义 baseline、tiered、tiered-review 和采用后 experience 变体；汇总器拒绝同 experimentId 下条件漂移。
- [x] 汇总器计算工程通过率、误通过率、人工介入、恢复率、总时长、首反馈和费用，报告内嵌所有成功/失败原始样本并禁止缺样本推断。
- [x] 自动验证已覆盖无批准、过期版本、源替换、并发撤销、远端冲突和中断不误发布；正式包可独立重算 SHA。真实团队对照样本尚未采集，报告协议明确该未覆盖范围。
- [x] 自动化、报告 schema 与相关失败验证已有可重复证据；根目录测试 300/300、桌面测试 69/69、桌面 E2E 主路径与候选采用路径通过。
- [ ] 固定条件下的真实团队对照样本仍需参与团队采集，未采集前不声明量化收益。

**范围限制：** 不把历史 benchmark 当作当前质量，不用未经测量的提升百分比。

**开发方式：** 先核对已有实现与未合并修改；沿上述用户行为打通所需状态、真实执行、界面和测试。必要整理先做且保持原行为；不要另拆为纯前端或纯后端票。若一个独立上下文无法完成，按可演示行为继续拆分。

**演示：** 从用户入口执行“交付结果”，展示成功成果、一个相关失败及恢复；以验收中的实际数据核对结果。
