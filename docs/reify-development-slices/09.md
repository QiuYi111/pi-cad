# 09：构建失败后定位并修复

**状态：** 已完成。

**当前进展（2026-09-06）：**

- 预览或应用失败会清除临时候选并继续显示最后已应用模型；失败参数、时间、诊断和可能原因保留在可折叠历史中。
- 错误区明确区分已知事实与诊断推测，主操作为恢复已应用值或把 artifact、候选参数和诊断交给 Agent 修复。
- Restore applied values 只撤销该参数候选并保留无关工作；迟到失败也受预览代次隔离。
- 真实集成测试以过大圆角触发构建失败，随后使用合法圆角恢复成功；桌面 E2E 验证旧模型仍为 part.step、诊断可回看并能恢复参数。

**交付结果：** 修改失败后仍显示上一份可用模型，用户能改参数或让 Agent 修复。

**前置依赖：** 08 选择已有参数并预览修改。

**验收条件：**

- [x] 保存失败修改、诊断和成功成果；清楚区分当前查看模型与失败候选，错误关闭后仍有入口。
- [x] 能确定位置时定位冲突，无法确定时显示已知信息与推测；主操作为修改参数或 Agent 修复。
- [x] 用过大圆角制造失败，再修复成功；恢复操作说明撤销哪些修改，不覆盖无关未保存内容。
- [x] 遵守总计划的共同完成标准，提交真实操作证据与相关失败验证。

**范围限制：** 不承诺所有几何错误都有面级定位。

**开发方式：** 先核对已有实现与未合并修改；沿上述用户行为打通所需状态、真实执行、界面和测试。必要整理先做且保持原行为；不要另拆为纯前端或纯后端票。若一个独立上下文无法完成，按可演示行为继续拆分。

**演示：** 从用户入口执行“交付结果”，展示成功成果、一个相关失败及恢复；以验收中的实际数据核对结果。
