# 12：工具结果直接进入成果列表

**状态：** 已完成（2026-03-10）。

**交付结果：** Agent 的检查图片、图表与模型自动可见，用户查看详情后能回到原成果。

**前置依赖：** 03 对话与画布平滑切换；11 快速测量与剖切。

**验收条件：**

- [x] 登记成果类型、身份、所属版本和来源；类型筛选与成果列表各负其责，比较作为操作。
- [x] 当前成果与指定 artifact 的检查参数不互相冲突；异步输出不会替换用户正在查看的其他成果。
- [x] 真实 Build 与 Probe 输出可点击查看、引用，坏输出显示失败；视角、视图、方案、版本有不同入口。
- [x] 遵守总计划的共同完成标准，提交真实操作证据与相关失败验证。

**范围限制：** 不引入额外通用插件框架。

**开发方式：** 先核对已有实现与未合并修改；沿上述用户行为打通所需状态、真实执行、界面和测试。必要整理先做且保持原行为；不要另拆为纯前端或纯后端票。若一个独立上下文无法完成，按可演示行为继续拆分。

**演示：** 从用户入口执行“交付结果”，展示成功成果、一个相关失败及恢复；以验收中的实际数据核对结果。

**实现与证据：**

- 大画布加入独立成果浏览器，按 All、Models、Results 筛选；每项展示 CAD/仿真/图片类型、current/head/commit/run 来源、角色及 SHA 或工具调用身份，Compare 仍是独立操作。
- Build、Probe 和生成图片的媒体输出自动进入成果列表；点击以全画布预览，`Back to model` 返回原成果，模型与视觉成果均能引用到对话。
- 手动选中的模型、外部打开的 STEP 以及对应检查状态互相隔离。异步 Build/Concept 完成时保留当前成果并显示带目标的通知，只有用户点击才切换。
- 桌面 E2E 实测打开 `imported.step` 后后台 Build 完成仍保持该模型，点击通知后切到 `part.step`；同时验证结果筛选、图片详情、返回模型和失败候选恢复。桌面生产构建与类型检查通过。
