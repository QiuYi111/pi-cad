# 22：人工批准、撤销与过期

**状态：** 已完成（2026-03-10；受信本地 OS 身份）。

**交付结果：** 有权限的人批准特定版本及范围，其他用户看到批准人和依据。

**前置依赖：** 21 提交候选并处理机器审查。

**验收条件：**

- [x] 首个企业落点使用 Electron 主进程读取的本地 OS 用户作为受信身份；renderer 不能提交 approver 字段，Agent API 完全没有 approve/revoke 操作，批准入口与 Agent 能力隔离。
- [x] 记录绑定 project、commit、workflow hash、Git source revision、完整 artifact set hash、scope、rationale、decision、approver 和时间。记录保存到项目外的应用数据目录，权限为 0600。
- [x] 只有机器审查已通过的 immutable named version 可批准；artifact、source 或 workflow 任一变化都会使旧批准失效。原批准人可带原因撤销；其他 OS 用户被拒绝。机器审查和 experience rating 明确保持独立。
- [x] 生产构建、人工批准测试 2/2 与 `git diff --check` 通过。

**范围限制：** 组织身份接入方式作为本票开工决策，不默认建设完整企业身份平台。

**开发方式：** 先核对已有实现与未合并修改；沿上述用户行为打通所需状态、真实执行、界面和测试。必要整理先做且保持原行为；不要另拆为纯前端或纯后端票。若一个独立上下文无法完成，按可演示行为继续拆分。

**演示：** 从用户入口执行“交付结果”，展示成功成果、一个相关失败及恢复；以验收中的实际数据核对结果。

**真实操作证据：** 测试以 alice 批准 manufacturing release，重新读取为 valid；把 artifact-a 换成 artifact-b 后同一记录立即 invalid。bob 撤销 alice 的记录被拒绝，alice 带 `superseded by a new design` 原因撤销成功；未通过机器审查的版本无法批准。UI 展示批准人、范围、依据、时间、有效/撤销状态。
