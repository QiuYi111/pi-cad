## 正式云端实测

2026-10-10，用户在原生客户端登录现有正式账户。使用部署地址 `https://desktop-pkr2go0.tailb53649.ts.net`，模型 `zai / glm-5.3-flash`，测试项目 `5ae8a628-e989-43f6-9725-151fa2fcba39`。由 `tests/real-cloud-e2e.cua.js` 分步操作真实窗口，不使用模拟服务或应用内捷径。

| 流程 | 结果 |
|---|---|
| 原生登录、创建测试项目、连接实际工作区 | 通过 |
| 从原 desktop 配置脚本读取云端可用模型，选择 GLM | 通过 |
| 真实模型生成长方体、STEP 和 STL | 通过 |
| STEP 由云端转网格，原生三维窗口显示 | 通过 |
| STL 下载后在原生三维窗口显示 | 通过 |
| 系统保存窗口下载两个文件 | 通过 |
| 本地独立检查文件内容、尺寸和体积 | 通过 |
| 断线点击重连；重启后打开原项目恢复长对话、文件与 STEP 预览 | 通过 |
| 重启后草稿、STL 预览、GLM 选择与最新回复保留 | 通过 |
| 真实 STL 上传后下载，字节和 SHA-256 一致 | 通过 |

| 强制退出后重新接入同一助手，进程编号不变，无重复进程 | 通过 |

下载的 STEP 为 6917 字节；二进制 STL 为 684 字节、12 个三角面。`tests/check-cloud-files.mjs` 直接读取下载文件，检查 STEP 格式完整性及 STL 尺寸 20×10×5 mm、体积 1000 mm³。STEP 精确几何体积由云端建模工具检查；本地脚本不解析 STEP 几何。

文件和证据：`test-results/real-cloud-20261010/real-cloud-e2e.step`、`real-cloud-e2e.stl`、`geometry.json`、`report.json`、`step-preview.png`、`stl-preview.png`、`restart-conversation.png`、`processes-before-quit.json`、`processes-after-quit.json`、`processes-before-crash.json`、`processes-after-crash.json`。

实测修复了空请求体被误标为 JSON、空回复中的模型错误被隐藏、长对话布局卡住。保存文件后操作工具曾无法读取窗口；应用采样显示主线程正常等待事件，重启测试应用后恢复。

重启检查还发现：退出时发出停止请求就断开连接，旧助手可能没收到请求。多个助手同时向同一日志追加状态，重开时会恢复旧分支。现已改为关闭输入、等待退出确认，再按需终止；按服务器、用户和项目保存助手编号，意外退出后重新接回。测试项目旧残留助手已停止，原日志保留。最终正常退出后进程数为 0；强制退出前后只有 1 个助手，进程编号均为 21358；正常重启后最新 `E2E-GLM-RESTORE-OK` 回复仍可见。修正后的 Swift 网络 E2E 和真实窗口复验通过，日志 `test-results/session-fix-build.log`。

## 范围

测试服务模拟云端账户、工作区和助手；HTTP、WebSocket、令牌续期、二进制消息、文件校验和原生界面使用实际客户端代码。服务会拆分含中文的消息，验证分段接收。

上方“自动 E2E”和“真实窗口 E2E”使用模拟服务；“正式云端实测”使用真实账户、GLM 和 CAD 计算。正式云端验收仅覆盖表中通过的流程；未验证其他模型、复杂装配或其他 macOS 版本。应用尚未做开发者发布签名和公证。
